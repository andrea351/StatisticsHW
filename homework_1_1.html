Homework 1.1: public-key cryptography in Ethereum

From a private key to a public key, one point at a time

Ethereum turns a secret number k into a public key Q with elliptic-curve scalar multiplication on secp256k1: Q = kG. Going forward is fast; going back is the elliptic-curve discrete logarithm problem. This page runs the same algorithm on a curve small enough to watch every step.

Toy public key Q = 6G = (5, 8) y² = x³ + 7 (mod 17), G = (1, 5), k = 6
1. Curve and key 2. G, 2G, …, kG 3. Slow motion 4. Statistics 5. Discussion 6. The real curve

1Define the toy curve, the base point and the private key

The curve is the set of points (x, y) with y² ≡ x³ + 7 (mod p), plus a point at infinity O that acts as zero. The homework uses p = 17, G = (1, 5) and k = 6. Larger primes are available for the statistics; the equation stays the same as in secp256k1 (a = 0, b = 7).

2Compute and print G, 2G, 3G, …, kG

Every step uses the point-addition rule. With slope λ, the sum of P = (x₁, y₁) and Q = (x₂, y₂) is x₃ = λ² − x₁ − x₂ and y₃ = λ(x₁ − x₃) − y₁. The slope is λ = (y₂ − y₁)/(x₂ − x₁) for two different points, or λ = 3x₁²/(2y₁) when a point is added to itself (doubling). Division means multiplying by the modular inverse, computed with the extended Euclidean algorithm.


  
Method 1: repeated addition

  
nG = (n − 1)G + G. It needs k − 1 additions, so it only works for small k.

  

  
Method 2: double-and-add (the faster method)

  
Read k in binary from the left. For every bit, double R; when the bit is 1, also add G. It needs about log₂ k operations, which is what makes 256-bit keys practical.

  

  

  






  
3Slow-motion view of the algorithm

  
Grey dots are all the points of the curve. Each addition draws the line through the two points (orange dots: modulo p a line is a set of points that wraps around the grid), marks where it meets the curve a third time, and reflects that point across the dashed middle line, because −y ≡ p − y.

  

    
    

      

        
        
        
        
        
      

      

      

      

    

  






  
4Statistical exploration

  
Repeat the computation for many values of k and for different base points, then look at what comes out. Consecutive k show the structure most clearly; random k (from a seeded generator, so results are reproducible) imitate how keys are chosen. SHA-256 of the same k is computed alongside as a reference for how a hash function behaves.
